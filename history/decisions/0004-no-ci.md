# 0004. No CI

**Rule:** There is no CI service and none is to be added. Verification is local.
Before a card moves to `complete/`, the checks defined by D-013 must have been
run locally on the platform(s) the change touches, and the result noted in the
card.

**Status:** Accepted · 2026-08-28
**Amends:** the CI-enforcement consequence of ADR-0001. ADR-0001's decision
stands unchanged; only its enforcement mechanism moves from CI to local checks.

**Why:** Principal's call — old-school, local verification. A CI provider is
configuration, credentials and failure modes the project does not want to carry.

**Cost accepted:** ADR-0001 requires every module to keep configuring
standalone. That property is not self-enforcing and now has nothing automatic
watching it, so it will rot silently unless the local check script actually
configures modules in isolation. The script is the substitute for CI, not a
convenience — without it ADR-0001 degrades to an unenforced intention.

**Rejected:** GitHub Actions, and any hosted runner — rejected by the principal.
