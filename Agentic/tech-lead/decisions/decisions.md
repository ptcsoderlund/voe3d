# Decisions

One line each: number, title, one sentence. Records 0001–0167 were written under the two earlier workflows and
live unchanged in `history/decisions/`, with their own index; `ADR-NNNN` in code means the record of that number
wherever it lives. Numbering continues here from 0168.

- `0168-the-agentic-workflow-replaces-specs-and-the-engines-rules-are-one-digest.md` — The Agentic workflow replaces specs; the old records move to `history/`; the engine's standing rules are restated once, numbered as code cites them.
- `0169-a-keysym-is-a-number-a-key-has-four-levels-and-altgr-is-a-place.md` — A keysym is a number as often as a name, a key has four levels, and AltGr is a place the keymap names.
- `0170-a-theme-is-read-in-theme-derived-in-ui-and-nearest-wins.md` — A theme is read in `theme`, derived in `ui`, and the nearest one wins.
- `0171-the-palette-is-derived-in-oklab-and-dark-mode-clamps-chroma.md` — The palette is derived in OKLab from one colour and two numbers, and dark mode clamps chroma.
- `0172-a-theme-is-one-file-in-a-themes-folder-and-a-program-remembers-it-by-file-name.md` — A theme is one file in a themes folder, and a program remembers which by its file name.
- `0173-a-code-subfolder-carries-its-own-index-page.md` — Every folder holding code carries `<folder>.md` as an index; `src/` and `tests/` entries move down out of the module page, `include/` gets a thin one.
- `0174-006s-finished-cards-are-merged-back-not-redone.md` — `feature/006-themes-old` is merged into `feature/006-themes` by the next `/drive`, with the four conflicts resolved as written; the planner then re-cuts `blocked/05`.
- `0175-a-new-folders-card-registers-it-in-the-build.md` — The build is the coder's: a card that creates a folder adds its `cmake/voe.cmake` row and root `add_subdirectory` line, and `checks.sh` allows those two files under a named decision.
- `0176-themes-row-names-render-for-its-tests-device.md` — `theme`'s row is 0170's plus `render`, so its test can make the headless device a label needs.
- `0177-to-see-what-was-drawn-render-to-a-png.md` — A coder checks what was drawn by rendering a PNG with `voe_editor --capture` or the headless app. The planner names this decision on cards that change what is drawn.
- `0178-two-built-in-themes-remembered-by-a-reserved-name.md` — The editor has two built-in themes, Near black (entry 0) and Near white (entry 1, light mode); the remembered line is `near_white` for Near white and empty for Near black.
- `0180-a-wayland-window-draws-at-the-compositors-fractional-scale.md` — On Wayland the window binds fractional-scale and viewporter, draws its buffer at the preferred scale, and reports its size and pointer in buffer pixels; closes D-188's Wayland half.
- `0181-bug-02-of-009-closed-as-the-compositors.md` — Bug 02 of 009 (keyboard held) did not reproduce after a reboot: closed as a transient Wayland/KWin fault, card 04 withdrawn; if it recurs, a new bug on its own feature starting from the four key tests.
- `0182-editor-text-keeps-scaling-and-hard-edges.md` — Editor text keeps scaling with the window (ADR-0104) and hard edges (ADR-0078); the edge cutoff is tuned so no stroke loses all its pixels, one pixel wider is accepted. Display-scale sizing and anti-aliased text were rejected.
- `0183-a-glyph-pixel-counts-if-it-is-within-049-of-a-pixel-of-the-outline.md` — The element pipeline's glyph cutoff moves 0.49 screen pixel outside the outline, measured from the sheet coordinates' derivatives, so no stroke of editor text vanishes; world text is unchanged.
- `0184-the-glyph-cutoff-sits-half-a-pixel-out-less-one-byte-step.md` — The glyph cutoff is `0.5 - 0.5 * field_per_pixel + 1/255`, clamped to 1/512..0.5, so an aligned outline keeps its width despite byte rounding; amends 0183's 0.49 margin.
- `0185-oxanium-is-the-only-font-and-pixel-operator-is-dropped.md` — Oxanium is the only font: Pixel Operator, its licence and the editor's font override are removed; both built-in themes use Oxanium, and any other `font=` falls back to it. Replaces 0179.
- `0186-the-road-to-a-game-and-the-first-game-is-a-coin-collecting-capsule.md` — Work moves toward one game, a third-person capsule that jumps and collects coins, in six milestones: build a level, Play, game logic, collision, a game, ship.
- `0187-game-logic-is-the-projects-own-c-and-play-starts-a-separate-program.md` — Game logic is C in the project written in an external editor; Play cooks, builds and starts the game as a separate program; visual logic comes later as an opt-in editor plugin.
- `0188-play-runs-the-scene-on-screen-unsaved-changes-included.md` — Play cooks the scene as it is on screen, unsaved changes included; it never saves or asks to.
- `0189-an-entity-is-a-number-a-material-is-an-instance-of-a-shader.md` — An entity is only a number and a new one's transform starts at the origin; a material is an instance of a shader, with separate shader and material editors later; until then a shape has only a colour.
- `0190-the-world-owns-which-rows-exist-a-system-owns-their-values.md` — A world holds entities and an entity owns its rows; rows are added (given bytes), removed and entities destroyed through `ecs`'s structural queue, applied once a frame before the systems; values stay the owning system's; every described type registers a default row. Amends rule 3.
- `0191-a-shapes-colour-is-a-described-linear-colour-drawn-through-its-object-record.md` — A shape has a `COLOUR` field (linear, default 0.7 grey) drawn through a colour in `voe_render_object`; capsule and cylinder are built-in kinds; derived rows are dropped through the queue.
- `0192-typing-into-a-value-and-picking-a-colour-are-uis.md` — `ui` holds one keyboard focus and its text for fields and typed number boxes; Enter/Tab/press elsewhere commit, Escape cancels; the colour picker is a `ui` panel the caller places.
- `0193-the-editor-changes-structure-through-the-queue-and-names-what-it-adds.md` — The editor's add, duplicate, delete and component changes are structural requests; new ids are max+1, names "Cube 2"; the Inspector shows described components only and learns what a type needs from `ecs`.
- `0194-colour-carries-no-meaning-in-an-editors-interface-a-theme-has-one-hue.md` — An editor interface's palette has one hue and roles differ only in lightness; no accent; state is shown by inversion, weight, borders and lightness; a theme authors `hue=` in place of `accent=` (no alias); a cooked game's GUI draws with a theme too, per-element property and theme overrides come later; level objects keep any colour. Replaces the accent in 0097/0171/0172.
- `0195-a-shapes-kind-is-chosen-from-a-list-in-the-inspector.md` — A shape's kind is a dropdown of the built-in kinds by name, a general named-list field the Inspector shows for any such field; changing it redraws live and marks unsaved. Amends 0191.
- `0196-state-is-drawn-inverted-and-a-palette-has-an-inverse-and-its-ink.md` — The accent roles become `inverse` (text_primary's lightness) and `inverse_ink` (ground's); held, dragged, selected and a field's selection draw inverted and labels inside take the ink; every role carries the one hue, chroma shrunk only for gamut; a slider is a number box with a thumb.
- `0197-slider-values-are-remembered-per-theme-in-one-settings-file.md` — Contrast and surface separation are remembered per theme in `<settings>/voe3d/theme_scalars` as `<contrast> <separation> <identity>` lines, written when a drag ends and on Reset; the theme file is never written.
- `0198-a-described-fields-values-can-be-named-and-a-named-field-is-a-dropdown.md` — A described field's values may be named in a table beside the struct's fields, and a tool shows an editable named field as a dropdown of those names; the field stays a UINT32 and the open list is the editor's own panel.
- `0199-an-overlay-belongs-to-the-widget-it-opened-from-and-swallows-the-cursor.md` — An open overlay is positioned from its widget every frame and clipped by the widget's panel, so it moves and disappears with it; it is opaque over its whole outline and nothing beneath it hovers or takes a click through the gaps between its items. Amends 0198.
- `0200-an-overlay-is-placed-to-fit-and-scrolls-when-it-cannot.md` — An open overlay picks its side each frame: its natural side when it fits, the opposite side when it does not, and when neither fits the roomier side, capped and scrolling inside itself so every item stays reachable; the wheel over an overlay scrolls it, not the panel. Amends 0199.
- `0201-the-engine-takes-the-fastest-card-and-says-which-it-took.md` — The engine picks its card by kind, not driver order, and always takes the fastest: discrete over integrated over software, never software silently, no power-saving override; it says on startup which card it took and why. Developer and player choice of card are later work.
- `0202-a-click-picks-by-a-ray-cast-against-the-shapes-own-triangles.md` — A click in a scene view names an entity by a ray cast on the CPU against the built-in shapes' own triangles, kept in an arena beside the ones the card holds; only shaped entities are picked, which is all an editor's project can draw.
- `0203-a-selection-outline-is-silhouette-quads-in-the-overlay-layer.md` — The selected entity is marked by its silhouette, built every frame as quads a fixed number of pixels wide and drawn as this frame's geometry in the overlay layer, in the lighter of the palette's two inverse roles; nothing is added to `render`.
- `0204-undo-is-a-line-of-scene-texts-and-a-step-is-what-an-edit-settles-into.md` — Undo is a line of whole-scene texts, the ones a save writes: an edit marks the history, the state is recorded when the editor comes to rest, and a step is read back into the same world with the selection re-found by its identity id.
- `0205-a-move-gizmo-is-3ds-geometry-and-ray-and-the-editors-drag.md` — The move gizmo's size, triangles, hit test and grab point are `3d`'s, drawn by the draw system after the outline behind a second depth clear in two colours; which handle is hovered or held, and the transform intent a drag submits, are the editor's alone.
- `0206-the-gizmos-axis-labels-are-strokes-in-its-own-geometry.md` — The X, Y and Z at the arrows' tips are camera-facing quads built by the same call as the arrows; `text` is not called and no distance-field material is made for them.
- `0207-a-handles-state-is-a-lightness-step-and-a-size-step.md` — A handle draws in the lighter of the palette's inverse pair, dimmed by a fixed fraction at rest and undimmed and a step wider while hovered or held, so state is lightness and size on the theme's own colour.
- `0208-015-is-proved-by-its-own-folders-and-the-cleanup-runs-next.md` — Feature 015 alone is proved by `checks.sh --folder` for 3d and editor plus the whole ctest suite, after clearing its own findings; a cleanup of the older cap findings runs right after it, and from then every feature is proved by `--all`.
- `0209-015-closes-on-its-walk-and-its-suite-card-is-dropped.md` — 015 is finished by the human's passing walk and its folder checks; the driver's `--all` suite card is deleted, not replanned, and its findings are work order 016's.
- `0210-016-moves-comments-and-splits-no-file.md` — Work order 016 changes comments and `.md` pages only, splits no file, moves a header's one-function reasoning above that function, and proves no code moved by comparing each file's tokens with HEAD's.
- `0211-a-folder-pages-opening-says-what-the-folder-is-for.md` — In 016, a folder page's opening over 400 characters keeps what the folder is for; each other claim goes to the header of the file that owns it, or the folder's public header, and is not repeated where a header already says it.
- `0212-the-glyph-cutoff-dilates-only-what-a-thin-stroke-needs.md` — The element glyph cutoff's dilation is no longer a fixed half pixel: it moves out only far enough to bring the face's thinnest stroke (two sheet texels) to a pixel and a quarter, so it is nought where text is about one texel per pixel and the letters keep the face's weight. Replaces 0184's fixed dilation.
- `0213-the-tree-stays-on-the-windows-drive-and-the-mount-carries-metadata.md` — The working tree stays at `/mnt/dev/GitRepos/Github/voe3d` because the human works on it from CLion on Windows; the drvfs mount must carry `metadata,uid=1000,gid=1000` or no build tree configures at all, both Checks stay as written and keep building in the tree, and a `configure_file ... Operation not permitted` means the mount is wrong, not the harness.
- `0214-cards-rank-by-kind-then-memory-and-render-says-so-in-one-line.md` — 0201's fastest card is the best kind (discrete, integrated, virtual, other, software last), then the largest device-local heap, among cards with Vulkan 1.3 and a drawing queue, the best that can present on a window; render prints one line at the choice naming the card, its kind, whether it fell back and from what, and the rate as the present mode.
- `0215-a-window-out-of-focus-draws-four-frames-a-second-and-a-hidden-one-none.md` — `voe_app_frame_open` paces a windowed program: focused, the present alone; unfocused, a quarter second between frames, woken early by any event; hidden (Wayland `suspended`, Windows minimised), no frames until shown or closing; `platform` says focused and visible and can wait; `voe_dev` opens on FIFO. Amends ADR-0131 for dev.
- `0216-a-wait-may-return-at-once-so-the-pace-is-kept-by-the-clock.md` — `voe_platform_window_wait`'s seconds is a ceiling, not a promise, because an unfocused Wayland window gets traffic every frame; `voe_app_frame_open` keeps the heartbeat as a loop over a pure step — ask the window and the clock, wait, poll, ask again — so focus, being shown and closing end it early while the clock ends it on time, a remainder under a millisecond draws, and a shell below xdg-shell 6 warns that it can never say suspended. Amends 0215's mechanism.
- `0217-things-are-made-as-an-entity-then-its-components.md` — The editor makes things only as Add entity (a bare transform at the origin, which cannot be removed) then Add component; no per-shape shortcut; Add component is a nested dropdown built from a menu path each component type declares.
- `0218-a-scene-has-exactly-one-camera.md` — Every scene has exactly one camera on its own entity, never none and never two: created with the scene, added to a scene opened without one, not deletable, its component not removable, never offered by Add component; no camera framework; filming elsewhere will be a separate render-to-texture thing.
- `0219-text-size-is-a-slider-per-theme-and-layout-fits-content.md` — A text-size slider (50–200 %, default 100) joins the theme sliders, remembered per theme in 0197's file and set back by Reset; it scales text only, and elements size to their content like a flexbox, with overflow rules where it does not fit; UI scale and per-element overrides are later.
- `0220-editor-layout-lives-in-the-global-editor-settings-file.md` — Panel sizes (Scene list, Inspector, top bar) are kept in one global editor settings file for the person, not the project, written when a resize ends; missing or unreadable means the defaults.
- `0221-a-component-types-menu-path-is-registered-in-ecs.md` — For 018: a component type's Add component path ("Rendering / Shape") is registered in `ecs` beside its needed type; parts split on `/`; a type with no path is never offered; the Inspector is handed identity and transform as kept, with no Remove; a submenu opens beside its row.
- `0222-a-thing-in-3d-space-is-placed-by-its-transform-and-the-camera-is-a-lens.md` — Anything in 3D space is placed only by its transform and nothing else in 3D space has one; the camera component is just the lens (fov, near, far), needs a transform, and the view is built from it with roll and scale, no camera-only exceptions; camera place/motion intents go, dev flies by transform intents, a first-person flight sim must be buildable; editor view cameras stay non-entity values and `3d`'s pick/gizmo/outline take a viewpoint value.
- `0223-the-scene-camera-is-seen-through-a-render-view-and-drawn-as-a-marker.md` — For 019: `3d` takes a `voe_render_view` as the viewpoint, built by `voe_3d_view` from a transform and a lens; a pose with no inverse is blind; the lens has a whole-lens replace intent; dev flies its own yaw/pitch; the camera is drawn as a box-and-frustum line marker that picks by its box; a 480×270 corner picture while it is selected; a new or old scene gets "Camera" at (0, 2, 6) looking at the origin; Delete and Duplicate refuse it.
- `0224-a-themes-text-scale-is-a-third-number-on-its-scalars-line.md` — For 020: text size is a scale 0.5–2.0 (default 1.0) on the theme's own `text_size`, `VOE_EDITOR_TEXT_SCALE_MIN/MAX` in the editor; kept as a third number in 0197's line `<contrast> <separation> <text_scale> <identity>`, old two-number lines read at 1.0; Reset drops the line.
- `0225-the-top-bar-is-as-tall-as-it-measured-last-frame.md` — For 020: the top bar is laid out at the height its content measured the frame before, `VOE_EDITOR_TOPBAR_HIGH` only the first frame's, so it grows and shrinks with the text; the dock gets the rest.
- `0226-a-side-panel-is-held-at-a-length-in-millimetres-and-kept-in-editor-settings.md` — For 021: a dock split may hold a child at a length in mm (Scene and Inspector 48 mm, min 30, a view keeps 40); the top bar is the larger of its measure and the person's height; a border is the seam ±0.5 mm, a double-click (0.4 s) restores the default; kept as `<key> <mm>` lines in `<settings>/voe3d/editor_settings`. Amends 0225.
- `0227-the-pointers-shape-is-named-by-platform.md` — For 021: `voe_platform_input_cursor` sets the arrow, left-right or up-down shape; Wayland by the optional cursor-shape-v1 (with tablet-v2's XML), Windows by `WM_SETCURSOR`; no cursor image.
- `0228-the-two-scene-views-share-the-middle-by-a-remembered-share.md` — For 022: the border between the two scene views drags like 0226's (pointer, minimum room, double-click to an even split); the views divide the middle by a share that holds as the window changes, kept in the editor settings.
