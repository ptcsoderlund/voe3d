# coder 117-15

## Learned
- "Wherever a rename or delete reads the materials table again, the trees table is read with it" was already true: voe_editor_models_materials_read reads the trees table, and assets_manage.c's materials_read refreshes the open tree, so nothing changed there.
- The species' own writes (tree_steps.c) were passed to voe_editor_disk_watch_wrote before this card but ignored as a kind not watched; now that `.tree` is watched they are told and take the stamp.

## Assumed
- A `.tree` changed on disk gets the same safety net as a material (tree_same: the strict read and the row compared as the text each writes), from 0509 point 1; the card said "as a material is".
- A `.tree` the trees table lacks (refused at the last read, or new since) is taken as true and changes nothing, since voe_editor_models_tree_changed ignores a missing row; the card named that call, not a table read.

## Surprised
- disk_watch.c keeps its own copy of the walked extensions rather than using assets_walk's list, so `.tree` had to be added there too for the watch to see it; the card named only assets_walk.
- Until card 16 lands, `voe_editor --check` asserts on any project holding a `.tree`: check.c's file_takes asserts on a listed kind it does not know.
- Undoing a file step for a `.tree` (or a `.material`) taken from disk changes the table but not the open copy in the Inspector, since undo.c's file step apply has no scene refresh; interface_read.c then pushes the stale shown copy back into the table, so the shown species and the file disagree.
