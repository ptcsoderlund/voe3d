# coder 114-01

## Learned
- slangc 2026.17 has no way to decorate SV_Position Invariant: `invariant`, `__invariant` are parse errors and `[vk::invariant]`/`[[vk::invariant]]` are unknown attributes; lay and shade's EQUAL rests on running one vertex entry from one module, layout and vertex input.
- The keep test needs the base colour's alpha, so the factor, distance-field and vertex-colour lines that form `base` became `voe_render_base` in draw.slang, shared by the main and depth fragments, so both read the same alpha.

## Assumed
- `voe_render_depth_fragment` returns void (no colour output) under the lay pipeline's write mask 0; the card's fallback (return a colour) applies only if validation warns.
- `voe_render_device_prepare`'s order comment in device.h now names lay and shade too, so it matches the prepare_steps comment the card named.

## Surprised
- On this machine the debug build could not load the validation layer ("best practices checks missing"), so render/prepare passed without checking whether validation warns about a fragment with no colour output under write mask 0.
