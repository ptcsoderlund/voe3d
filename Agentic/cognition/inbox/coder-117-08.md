# coder 117-08

## Assumed
- Under a splash, `voe_game_trees_grow` runs only when at least one species is marked. A project's first update marks them all, so it still grows them all. A splash over the same folder with nothing changed grows nothing. I did this so that an import's or a load's splash does not regrow every tree each time.
- A row counts as read anew if it is new, if its values differ from the last read, or if it was still marked before the read. Without the third case, a pending regrow would be lost when an Assets command re-reads the tables.
- `trees_read` marks by comparison, so a rename regrows the species under its new path. The store's rename has already moved its entries there.
- A busy job is cancelled when the folder changes or before a whole grow. The job has no cancel, so it is destroyed, which waits out its burst, and a new one is made.
- If a stop is asked, a whole grow leaves its marks set, and the job finishes the species frame by frame afterwards.

## Surprised
- The species table caps at `VOE_EDITOR_TREES` 32. In practice the store's 128 entries limit it first, since each species takes 1 plus its variations.
