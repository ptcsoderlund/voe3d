# coder 117-04

## Assumed
- "Held as the store refers to entries" read as indices into the store's table (VOE_3D_MODELS for none): indices stay put until _clear, which empties the species too, so a rename needs nothing more for the species' variations to follow.
- A species is an entry with `variation_count` > 0; it is kept at stamp 0, loaded, partless, through the store's own keep, so _find, _count and _clear see it like any entry.
- _species_set holds whatever `path#<v>` entries are already in the store, and _variation checks the held one is loaded at lookup; a variation put after the set is not held until the set is called again. The card did not say which order the caller uses.
- The rename's `from#<v>` rule is in the tail match shared by every rename path, so a layer's or kind's material path `from#...` would move too; no such paths exist today.
